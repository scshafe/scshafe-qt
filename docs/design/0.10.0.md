# 0.10.0 design note: SuiInfoTip, the hideable sidebar, SuiListHeader

Owner request of 2026-11-02, for voice-lab first and every scshafe-qt app after.
Three additions, then the 0.10.0 release. All are additive: nothing that exists
changes its API or its default behaviour. The voice-lab agent's request (an
`agent-request` issue) settles its exact needs. Where it differs from this note,
the request wins and this note is updated in the PR that builds the component.

Sizes and timings are new NATIVE-ONLY tokens in `tools/gen_tokens.py`, never
literals in a component:

| Token | Value | Use |
|---|---|---|
| `controlHeightSm` | 24 | compact controls: the compact search field, the filter button |
| `infoTipSize` | 20 | the info button |
| `infoTipMaxWidth` | 320 | popover text width (the web tooltip's cap) |
| `infoTipDelay` | 400 ms | hover before it opens (the web HoverCard's `openDelayMs`) |
| `infoTipCloseDelay` | 120 ms | grace after the pointer leaves (HoverCard's `closeDelayMs`) |
| `sidebarRevealSize` | 24 | the hidden sidebar's hot zone (a square) |
| `sidebarRevealDelay` | 150 ms | dwell in the hot zone before it reveals |
| `sidebarHideDelay` | 400 ms | after the pointer leaves, before it slides away |
| `filterBadgeSize` | 14 | the active-filter count on the filter button |

New built-in icons: `help` (a circled question mark) and `pin`.

## 1. SuiInfoTip

A small info button that shows a popover with details, so secondary text can
leave the layout.

```qml
SuiInfoTip {
    title: "Trim"
    text: "Drag a handle to keep part of the take. <b>Save</b> writes the trim."
}
```

API:
- `title`: plain text.
- `text`: the body, in a small markup subset (below).
- `textFormat`: `Text.StyledText` (default, the subset) or `Text.PlainText`.
- `label`: the accessible name. Default "About <title>", or "More information"
  without a title.
- `iconName`: `info` (default) or `help`.
- `placement`: `"below"` (default) or `"above"`, the preferred side.
- `delay`: the hover delay (`SuiTheme.infoTipDelay`).
- `open()`, `close()`, `toggle()`, `opened`, `linkActivated(link)`.

Behaviour:
- **Hover**: it opens after `delay`. It closes `infoTipCloseDelay` after the
  pointer leaves both the button and the popover. Moving into the popover keeps
  it open, so a link can be clicked.
- **Click**: opens it and pins it. A pinned tip ignores the pointer leaving and
  closes on a click outside or on the button again. A click on a tip that hover
  opened pins it instead of closing it.
- **Keyboard**: the button is a Tab stop and shows its ring for keyboard focus
  only. Space/Return toggle the tip and Esc closes it. Esc propagates when the
  tip is closed, so a dialog still closes. Focus leaving the button closes a tip
  the keyboard opened.
- **Never steals focus**: a click does not focus the button (`Qt.TabFocus`), and
  the popover never takes focus (non-modal, `focus: false`). An app's keys, such
  as voice-lab's R / Space / Return, keep working with a tip open. Esc reaches
  the tip only through the focused button: a window-wide Esc would take Escape
  from the app.
- **Placement**: centred on the button, on the preferred side. It flips when
  that side has no room and the other has more, and is kept `spaceSm` inside
  the window (Popup `margins`). It is an in-window popup, as SuiSelect's list is.
- **Look**: the popover surface, `borderStrong`, `radiusLg` and the
  `spaceSm`/`spaceMd` padding. The title is `fontSizeMd`, strong and
  `textStrong`. The body is `fontSizeSm`, `text`, wrapped at `infoTipMaxWidth`.
  It fades on `SuiTheme.duration`.
- **Accessible**: the button is a Button named by `label` and described by the
  title and the plain body. VoiceOver therefore reads the details without the
  popover opening. The popover is a HelpBalloon named by the title.

**Rich text without the beacon.** The module renders caller text as plain text
everywhere (the 0.1.x mail-subject `<img>` beacon). The body is the one
exception, and it is sanitised before Qt sees it:
- `<b>`, `<strong>`, `<i>`, `<em>`, `<code>`, `<br>`, `<p>`, `<ul>`, `<ol>`,
  `<li>` and `<a href="…">` pass through with every other attribute dropped.
- Any other tag, and a stray `<` or `&`, is shown as text.
- `<img>`, `<font>` and styles never render, so nothing is fetched.
- Links only emit `linkActivated` and never open by themselves.
- `tests/test_plain_text.py` gains the tip with the beacon payload: zero hits,
  and the tag shown as text.

## 2. The hideable sidebar (SuiAppShell)

The sidebar is docked or hidden. This is an opt-in addition to the shell, not a
new component, because the shell owns the pane. It builds on the existing
`sidebarOpen`: open means docked, closed means hidden.

```qml
SuiAppShell {
    sidebarHideable: true
    sidebarShortcut: "Ctrl+Meta+S"   // ⌃⌘S on macOS; the app chooses
    settingsCategory: "shell"        // persist docked/hidden and the width
    ...
}
```

New API:
- `sidebarHideable`: false by default.
- `sidebarShortcut`: "" (none).
- `settingsCategory`: "" (not persisted).
- `sidebarRevealTop`: the hot zone's top edge. It defaults to
  `SafeArea.margins.top`.
- `sidebarRevealed`: read-only; true while the sidebar shows as an overlay.
- `pinLabel`: "Pin sidebar".

Behaviour:
- **Pin**: with `sidebarHideable`, a pin button (`pin` icon, checkable, checked
  while docked) sits in the sidebar's top-right corner. In the docked sidebar it
  hides the sidebar; in the overlay it docks it. The app's sidebar content leaves
  that corner free.
- **Hot zone**: while hidden, a `sidebarRevealSize` square sits at the content's
  top-left. Its top edge is `sidebarRevealTop`. A HoverHandler only: clicks and
  hover still reach the content under it.
  - Dwelling `sidebarRevealDelay` in it slides the sidebar in as an overlay
    above the content. The content does not move or reflow.
  - The overlay stays while the pointer is over it and slides away
    `sidebarHideDelay` after the pointer leaves.
  - Focus inside the overlay moves to the content when it slides away, as for a
    collapse today.
  - The overlay draws its right edge in `borderStrong` with a `shadowColor`
    fade, over an opaque surface.
- **macOS title bar**: in a window that extends its content under the title bar
  (`Qt.ExpandedClientAreaHint`), the hot zone sits below the title bar and never
  over the traffic lights. `SafeArea.margins` is relative to the shell and covers
  the title bar there. In an ordinary window it is 0, which is already below the
  title bar. An app that draws its own title band sets `sidebarRevealTop`.
- **Shortcut**: `sidebarShortcut` (Qt.WindowShortcut) calls `toggleSidebar()`:
  docked ↔ hidden. It works from the overlay too, where it docks.
- **Persistence**: with `settingsCategory`, the shell keeps `sidebarOpen` and
  `sidebarWidth` in QtCore `Settings` (already in PySide6-Essentials). It
  restores them on load and writes them on change. Like any QSettings use, the
  app sets `organizationName` and `applicationName`. A bound `sidebarOpen` would
  be replaced on restore, so the README says not to bind it then.
- **Motion**: docking and hiding move the content on `SuiTheme.duration`, as a
  collapse does today. The overlay slides in on `SuiTheme.duration * 2` and out
  on `SuiTheme.duration`, as SuiSheet does. Under reduced motion both are
  instant. The delays stay, because they are not motion.
- **Collapse now slides**: a collapsing sidebar now slides out at its full width
  instead of being squeezed, so the overlay and the docked pane are the same
  item. The inspector is unchanged.
- **Accessible**: a hidden sidebar stays out of the Tab order. Keyboard and
  VoiceOver users dock it with the shortcut or `toggleSidebar()`; hover reveal
  is a pointer convenience. The pin is a CheckBox named `pinLabel`. The overlay
  is the same Pane, named `sidebarLabel`.

## 3. SuiListHeader

A compact header for above a list: a search field, an optional result count and
a filter button that opens a menu of filters.

```qml
SuiListHeader {
    searchLabel: "Search prompts"
    filters: [
        { key: "missing", text: "Missing", section: "Show", exclusive: true },
        { key: "kept", text: "Kept", section: "Show", exclusive: true },
        { key: "long", text: "Long-form", section: "Labels" }
    ]
    activeFilters: ["long"]
    resultCount: 12; totalCount: 340
    onTextEdited: library.setSearch(text)
    onFilterToggled: (key, active) => library.setFilter(key, active)
}
```

- **Compact search field**: SuiSearchField gains `compact` (false by default).
  A compact field is `controlHeightSm` high, uses `fontSizeSm` and has
  `iconSizeSm` icons. This is the size the header uses.
- **Search API**:
  - `text` (alias), `searchLabel`, `placeholderText`, `searchField` (read-only
    alias).
  - `textEdited()` and `cleared()` are forwarded from the field.
  - `focusShortcut` defaults to "Ctrl+F", which is ⌘F on macOS. It focuses and
    selects the search from anywhere in the window, a text field included.
  - Esc clears the field, then propagates once it is empty (SuiSearchField's
    behaviour).
- **Filter API**:
  - `filters`: an array of `{ key, text, section?, exclusive? }`. Options in a
    section marked `exclusive` act as one choice: choosing one clears the others.
  - `activeFilters`: the active keys. The header updates it as filters are used,
    and the app may set it.
  - `filterToggled(key, active)`, `filtersCleared()`, `clearFilters()`,
    `filterLabel` ("Filters").
- **Filter button**: a `controlHeightSm` square with the `filter` (funnel) icon,
  hidden when `filters` is empty. While any filter is active it is tinted (the
  checked look: accent icon and fill) and carries the count in a
  `filterBadgeSize` pill at its corner.
- **Filter menu**: a T.Menu. Each section has a header like SuiSidebarList's,
  over checkable items. A separator follows, then "Clear filters", which is
  disabled while none is active. It closes after a choice, as native menus do.
  - Keyboard: Space/Return/Down on the button open it at the first item.
    Up/Down move, Space/Return choose, and Esc closes and returns focus to the
    button.
- **Count**: `resultCount` (-1 hides it) and `totalCount` show "12" or
  "12 of 340"; `countText` can override the text. It is `fontSizeSm`, muted and
  tabular.
- **Accessible**:
  - The header is a ToolBar named `label` ("Search and filters").
  - The search is an EditableText named `searchLabel`.
  - The filter button is a ButtonMenu named `filterLabel`, described as
    "2 active: Missing, Long-form" or "None active".
  - Menu items are checkable MenuItems, and the count is StaticText.

## Tests

Each component joins the shared contract:
- a `SPECS` entry (both themes, role and name, the keyboard ring pixel, pointer
  focus; for the tip, a click must not focus);
- a QML `TestCase`;
- the gallery;
- the README table;
- the `check_dist.py` smoke scene;
- the plain-text test.

The behaviour tests, per component:
- `tests/test_infotip.py`:
  - opening: hover opens after the delay and not before, leaving closes after
    the grace, and moving into the popover keeps it open;
  - pinning: a click pins it; a second click or a click outside closes it;
  - focus: a click leaves focus (and an app key handler) where it was;
  - keyboard: Tab, then Space/Return/Esc, then Tab away;
  - placement: below, flipped above at the bottom edge, inside the window at
    the right edge;
  - the accessible description;
  - the markup subset: links, the beacon, `<` and `&`;
  - reduced motion.
- `tests/test_shell.py`:
  - the pin hides and docks;
  - dwelling in the hot zone reveals the overlay, and the content x and width
    do not change;
  - the overlay stays while hovered and slides away after the delay;
  - the hot zone starts at `sidebarRevealTop`;
  - the shortcut toggles;
  - focus leaves a concealed overlay;
  - persistence (a Settings `location` in a temp dir);
  - reduced motion;
  - the existing shell tests still pass.
- `tests/test_list_header.py`:
  - the compact heights;
  - ⌘F from another text field;
  - Esc clears;
  - the menu by pointer and by keyboard;
  - toggling, exclusive sections and Clear;
  - the tint, the badge and the accessible description;
  - the count text.
